# 工作模式指南

不同场景下如何使用 Codex 的最佳实践。

## 模式一览

| 模式     | 场景               | 沙箱            | 说明                        |
| -------- | ------------------ | --------------- | --------------------------- |
| 深度分析 | Bug 排查、架构理解 | read-only       | 让 Codex 搜索和分析代码     |
| 代码审查 | 提交前审查         | read-only       | Codex 审查 diff 并给出建议  |
| 并行研究 | 多个不相关问题     | read-only       | 同时启动多个 Codex 任务     |
| 辅助实现 | 需要 Codex 写代码  | workspace-write | Codex 直接修改文件          |
| 方案探索 | 对比多种方案       | read-only       | 让 Codex 分析不同方案的优劣 |

## 模式详解

### 深度分析

**场景：** 遇到复杂 Bug，需要在大型代码库中追踪调用链、理解数据流。

**流程：**

1. 主 AI 描述问题并提供已知线索
2. Codex 在代码库中搜索和分析
3. Codex 返回分析结论（可能包含文件路径、行号、调用关系）
4. 主 AI 用 `read_file` 验证关键位置
5. 主 AI 做实际修复

**prompt 模板：**

```
在 <项目目录> 代码库中，存在以下问题：
<问题描述>

已知线索：
- <线索1>
- <线索2>

请分析：
1. 问题的根本原因
2. 相关的代码路径（列出文件和行号）
3. 建议的修复方案
```

### 代码审查

**场景：** 提交代码前，让 Codex 从不同视角审查变更。

**流程：**

1. 主 AI 执行 `codex exec review --uncommitted -o result.txt`
2. 读取审查结果
3. 根据审查意见决定是否需要修改

**适用时机：**

- 大型重构后
- 涉及安全相关的改动
- 不确定改动是否有副作用

### 并行研究

**场景：** 有多个不相关的问题需要调查。

**流程：**

1. 为每个问题构造独立的 prompt
2. 分别在不同的后台终端启动 Codex
3. 等待全部完成
4. 逐个读取结果并综合分析

详见 [并行执行指南](./parallel.md)。

### 辅助实现

**场景：** 让 Codex 生成代码草稿或脚手架。

**注意事项：**

- 使用 `workspace-write` 沙箱
- 任务完成后必须审查 Codex 生成的代码
- 不要对 Codex 的产出盲信，主 AI 负责质量把关

**流程：**

1. 主 AI 给出详细的实现规格
2. Codex 生成代码
3. 主 AI 审查、修改、完善

### 方案探索

**场景：** 面对设计决策，需要分析不同方案的优劣。

**prompt 模板：**

```
我们在 <项目> 中需要实现 <功能>。有以下几种方案：

方案 A：<描述>
方案 B：<描述>

请分析每种方案的：
1. 优点
2. 缺点
3. 实现复杂度
4. 对现有代码的影响范围

基于实际代码库的情况，推荐哪种方案？
```

## 什么时候该/不该用 Codex

### 适合委派给 Codex

- 大范围的代码搜索（"找出所有用了某个 API 的地方"）
- 复杂的调用链追踪
- 代码审查
- 架构分析
- 方案对比研究

### 不适合委派

- 简单的单文件修改（直接做更快）
- 需要与用户实时交互的任务
- 涉及敏感信息的操作
- 主 AI 已经有足够上下文的简单问题

## Prompt 质量检查清单

在调用 Codex 前，检查 prompt 是否满足：

- [ ] 问题描述清晰具体
- [ ] 提供了相关的文件路径或目录范围
- [ ] 包含已知的上下文和线索
- [ ] 明确了期望的输出格式
- [ ] 如果需要 Codex 搜索，指定了搜索的起点或关键词
